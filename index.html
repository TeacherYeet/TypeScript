Week 1

Waarom TypeScript + je eerste types

Je ontdekt hoe TypeScript fouten vindt vóórdat je code draait, en je repareert een kassasysteem vol bugs.

2 lesurenBestand: week1/kassa.tsTest: npm run test:week1

Leerdoelen

  • Ik kan uitleggen wat TypeScript toevoegt aan JavaScript.
  • Ik gebruik de types string, number, boolean, any en unknown.
  • Ik weet wanneer TypeScript zelf het type raadt (type inference).

Uitleg

TypeScript = JavaScript + types

TypeScript is gewoon JavaScript, maar je kunt erbij zetten wat voor soort waarde een variabele of parameter is. De TypeScript-compiler (tsc) controleert dat. Daarna haalt hij de types weg en blijft er normale JavaScript over.

let naam: string = "Sam";
let leeftijd: number = 17;
let geslaagd: boolean = true;

leeftijd = "zeventien"; // ❌ Type 'string' is not assignable to type 'number'

Type inference: TypeScript raadt mee

Je hoeft niet overal een type bij te schrijven. Geef je meteen een waarde, dan weet TypeScript het type al.

let prijs = 2.5;   // TypeScript weet: prijs is een number
prijs = "gratis";   // ❌ fout

Bij parameters van functies kan TypeScript niet raden wat er binnenkomt. Daar schrijf je het type dus wel zelf:

function verdubbel(x: number): number {
  return x * 2;
}
//                  ↑ parameter      ↑ returntype (wat de functie teruggeeft)

any en unknown

any zet de controle uit: alles mag, dus TypeScript vangt ook geen fouten meer. unknown betekent "ik weet het nog niet". Dan moet je eerst controleren wat het is voordat je ermee werkt.

let a: any = "hallo";
a.bestaatNiet();          // geen fout van TypeScript, wel een crash als het draait

let b: unknown = "hallo";
b.toUpperCase();          // ❌ TypeScript: eerst controleren!
if (typeof b === "string") {
  b.toUpperCase();        // ✅ nu weet TypeScript dat b een string is
}

Een interface voor een object

Wil je beschrijven hoe een object eruitziet? Dan gebruik je een interface. Met export kunnen andere bestanden (zoals de tests) hem gebruiken.

export interface Product {
  naam: string;
  prijs: number;
}

strict-modus: in deze course staat de strenge controle van TypeScript altijd aan. Daardoor moet elke parameter een type hebben en mag een functie niet "soms niets" teruggeven.

Week 2

Functies, objecten en eigen types

Je beschrijft je eigen data met een interface en bouwt een cijferadministratie.

2 lesurenBestand: week2/student.tsTest: npm run test:week2

Leerdoelen

  • Ik geef parameters en returnwaarden van functies een type, ook optionele en default parameters.
  • Ik beschrijf een object met een interface of type, met optionele (?) en readonly velden.
  • Ik kan het verschil tussen type en interface uitleggen.

Uitleg

Functies met types

function groet(naam: string, aanhef: string = "Hoi"): string {
  return `${aanhef} ${naam}`;
}
groet("Sam");            // "Hoi Sam"  (aanhef heeft een default)

function log(bericht: string, extra?: string): void {
  console.log(bericht, extra ?? "");
}
// extra? = optioneel. void = de functie geeft niets terug.

Een interface met optionele en readonly velden

interface Docent {
  naam: string;
  readonly personeelsnummer: number;  // mag na het maken niet meer veranderen
  vakken: string[];
  telefoon?: string;                     // optioneel: mag ontbreken
}

const d: Docent = { naam: "Mo", personeelsnummer: 42, vakken: ["TS"] };
d.vakken.push("Python");   // ✅ mag
d.personeelsnummer = 7;    // ❌ readonly

Functies die een object gebruiken

function aantalVakken(docent: Docent): number {
  return docent.vakken.length;
}

function voegVakToe(docent: Docent, vak: string): void {
  docent.vakken.push(vak);   // past de array in het object aan
}

type of interface?

Voor objecten mag allebei. Een type kan daarnaast ook andere dingen beschrijven, zoals een keuze tussen waarden (type Id = string | number). Afspraak in deze course: interface voor objecten, type voor de rest.

Week 3

Arrays, union types en narrowing

Je modelleert data die meerdere vormen kan hebben, zoals de status van een bestelling of een betaalmethode.

2 lesurenBestand: week3/winkelmandje.tsTest: npm run test:week3

Leerdoelen

  • Ik type arrays (Product[]).
  • Ik gebruik union types (string | number) en literal types ("open" | "betaald").
  • Ik maak een type smaller met typeof, in en een discriminated union (narrowing).

Uitleg

Union en literal types

let id: string | number;      // óf een string, óf een number
id = "A12";  // ✅
id = 12;     // ✅

type Lampje = "rood" | "oranje" | "groen";   // alleen deze drie teksten
let l: Lampje = "blauw";   // ❌ fout

Narrowing: het type smaller maken

Bij een union weet TypeScript niet welke van de twee het is. Met een controle maak je het type smaller:

function toon(id: string | number): string {
  if (typeof id === "number") {
    return id.toFixed(0);      // hier is id een number
  }
  return id.toUpperCase();     // hier is id een string
}

Discriminated union

Objecten met verschillende velden geef je één gezamenlijk veld met een vaste tekst, bijvoorbeeld soort. Aan dat veld ziet TypeScript welke variant het is.

type Bezorging =
  | { soort: "thuis"; adres: string }
  | { soort: "afhaalpunt"; puntNaam: string };

function label(b: Bezorging): string {
  switch (b.soort) {
    case "thuis":      return `Naar ${b.adres}`;      // b.adres bestaat hier
    case "afhaalpunt": return `Ophalen bij ${b.puntNaam}`;
  }
}

Een nieuwe array maken in plaats van aanpassen

Later (bijvoorbeeld in React of bij undo-functies) is het belangrijk dat je de originele array niet verandert. Maak liever een nieuwe:

const lijst = [1, 2];
const erbij  = [...lijst, 3];               // [1, 2, 3]  lijst blijft [1, 2]
const zonder = lijst.filter((x) => x !== 1);  // [2]        lijst blijft [1, 2]

Generics, modules en data van een API

Je verdeelt je code over bestanden, haalt data op van een API en schrijft je eerste generieke functie.

2 lesurenBestanden: week4/types.ts, api.ts, todos.ts, hulp.tsTest: npm run test:week4

Leerdoelen

  • Ik verdeel code over bestanden met import en export.
  • Ik gebruik async/await en fetch, en geef het antwoord van een API een type.
  • Ik schrijf een eenvoudige generic, zoals function eerste<T>(lijst: T[]).

Uitleg

Modules: import en export

// types.ts
export interface Film { titel: string; jaar: number }

// films.ts
import { Film } from "./types";   // accolades + exact dezelfde naam
export function nieuwste(films: Film[]): Film[] { /* ... */ }

async, await en fetch

Data ophalen duurt even. Een async-functie geeft daarom altijd een Promise terug: een belofte dat de waarde straks komt. Met await wacht je op die waarde.

async function haalFilmsOp(): Promise<Film[]> {
  const res = await fetch("https://voorbeeld.nl/films");
  const data = await res.json();
  return data as Film[];   // jij vertelt TypeScript wat er binnenkomt
}

Let op: TypeScript controleert níet of de API echt een Film[] stuurt. Types bestaan alleen tijdens het compileren. Klopt je type niet met de echte data, dan merk je dat pas tijdens het draaien.

Fouten afvangen

try {
  const res = await fetch(url);
  if (!res.ok) { /* bijv. 404 of 500: fetch gooit dan GEEN fout, controleer zelf */ }
} catch (e) {
  // geen internet, ongeldige url ...
}

Generics: een functie voor elk type

Een generic is een "type-variabele", meestal T. TypeScript vult zelf in wat T is, op basis van wat je meegeeft.

function laatste<T>(lijst: T[]): T | undefined {
  return lijst[lijst.length - 1];
}
const a = laatste(["x", "y"]);   // a: string | undefined
const b = laatste([1, 2, 3]);   // b: number | undefined

Week 5

Classes en OOP

Je bundelt data en gedrag in een class, schermt gegevens af met private en bouwt verder met extends en implements.

2 lesurenBestanden: week5/bankrekening.ts, vormen.tsTest: npm run test:week5

Leerdoelen

  • Ik maak een class met een constructor, properties en methodes.
  • Ik gebruik private, protected en readonly om data te beschermen.
  • Ik gooi een fout met throw new Error(...).
  • Ik gebruik extends (overerving) en implements (een interface volgen).

Uitleg

Een class

Een class is een bouwtekening voor objecten. Met new maak je een object; dan draait de constructor. Met this verwijs je naar het object zelf.

class Teller {
  readonly naam: string;      // alleen in de constructor te zetten
  private stand: number;      // van buitenaf niet te lezen of te wijzigen

  constructor(naam: string, start: number = 0) {
    this.naam = naam;
    this.stand = start;
  }

  verhoog(stap: number): void {
    if (stap <= 0) throw new Error("Stap moet groter dan 0 zijn");
    this.stand += stap;
  }

  getStand(): number {
    return this.stand;
  }
}

const t = new Teller("bezoekers");
t.verhoog(3);
t.getStand();   // 3
t.stand = 99;    // ❌ stand is private

Overerving met extends

Een subclass krijgt alles van de ouder-class en kan iets toevoegen. Wil de subclass bij een veld van de ouder kunnen? Maak dat veld dan protected in plaats van private.

class Stappenteller extends Teller {
  verdubbel(): void {
